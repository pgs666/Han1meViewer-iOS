## What Changed

- Reviewed all commits and source changes between `v0.2.0` and `main`.

- Updated the app marketing version from `0.2.0` to `0.2.1`.
- Updated the Release workflow to publish the version-specific maintained release-note file instead of a generic generated summary.
- Pushed the release preparation to `main` and dispatched the Release workflow for version `0.2.1` with prerelease enabled.

## Why

The release page should explain the user-visible behavior changes clearly and use the same wording style as previous releases. Reading a versioned note file from the workflow also keeps the GitHub Release body identical to the reviewed repository copy.

## Verification

- Confirmed `v0.2.1` did not already exist as a tag or GitHub Release before dispatch.
- Reviewed the complete `v0.2.0..main` diff and categorized four user-facing changes plus one documentation-only maintenance commit.
- The Release workflow runs shared JVM tests and builds the unsigned iOS device app before publishing.
- The workflow result, prerelease flag, release body, attached IPA, and downloaded IPA archive are verified after dispatch.

## Limits

- The published IPA is unsigned and must be signed before device installation.
- The release workflow requires a matching `docs/release-notes/vX.Y.Z.md` file for future versions.
